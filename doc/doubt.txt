INTRODUCTION                                              *doubt-introduction*

doubt.nvim helps review code by attaching persistent claims directly to files.
Claims stay grouped in sessions, render inline and in the side panel, and can be
exported as XML or wrapped handoff prompts for downstream agents.

Built-in claim kinds:

- question
- concern
- reject

===============================================================================
REQUIREMENTS                                              *doubt-requirements*

- Neovim 0.10+
- MunifTanjim/nui.nvim

===============================================================================
INSTALLATION                                              *doubt-installation*

Example with lazy.nvim:

>
	{
		"makefinks/doubt.nvim",
		dependencies = { "MunifTanjim/nui.nvim" },
		config = function()
			require("doubt").setup()
		end,
	}
<

After installation, run `:DoubtPanel` to confirm the plugin loaded.

COMMANDS                                                      *doubt-commands*

Main review actions:

- `:DoubtQuestion [note]`
- `:DoubtConcern [note]`
- `:DoubtReject [note]`
- `:DoubtClaim <kind> [note]`
- `:DoubtClaimDelete`
- `:DoubtClaimKind <kind>`
- `:DoubtClaimNote [note]`
- `:DoubtClaimToggle`
- `:DoubtPanel`
- `:DoubtExport [template]`
- `:DoubtExportFilter`
- `:DoubtExportXml`
- `:DoubtHealthcheck`
- `:DoubtClearBuffer`
- `:DoubtRefresh`
- `:DoubtState`

Session management:

- `:DoubtSessionNew [name]`
- `:DoubtSessionResume [name]`
- `:DoubtSessionStop`
- `:DoubtSessionDelete [name]`
- `:DoubtSessionRename [name] [new_name]`

Without an explicit range, `:DoubtQuestion`, `:DoubtConcern`, `:DoubtReject`,
and `:DoubtClaim <kind>` act on the current line. With a visual or Ex range,
they use that range instead.

When a note argument is omitted, range claims are edited directly in a
borderless editor inside the rendered claim block. Use `<S-CR>` or `ZZ` to
save. Use `ZQ`, `q`, or normal-mode `<Esc>` to cancel. `<CR>` inserts a new
line. Set `input.mode = "popup"` to use the bordered popup editor instead.

Built-in export templates:

- `raw`
- `review`
- `multi_agent`

===============================================================================
KEYMAPS                                                        *doubt-keymaps*

Default mappings:

- `<leader>Dq` question the current line or selection
- `<leader>Dc` flag concern on the current line or selection
- `<leader>Dr` reject the current line or selection
- `<leader>Dp` toggle the panel
- `<leader>De` copy the active session handoff
- `<leader>DE` pick an export template, then copy handoff
- `<leader>Db` clear all doubt claims for the current buffer
- `<leader>Dd` delete claim nearest to the cursor
- `<leader>Dm` modify claim note nearest to the cursor
- `<leader>Dk` modify claim kind nearest to the cursor
- `<leader>Dt` toggle expanded claim note nearest to the cursor
- `<leader>Dn` start a new session
- `<leader>Ds` resume a saved session
- `<leader>Dx` stop the active session
- `<leader>Df` refresh decorations and panel state

Set `keymaps = false` to disable all defaults.

REVIEW RUNS                                                *doubt-review-runs*

In a Git repository, `:DoubtExport` records the exact working tree at handoff
time and asks the agent to write a claim-to-change manifest under
`.doubt/runs/<run-id>/results.json`.

Run `:DoubtRefresh` or press `r` in the panel after the agent finishes. Each
reported claim displays the agent summary in a separate response block.
Validated changes display `[+N code changes] [D: view diff]` in the response
header, where N is the number of attributed diff hunks. Ordinary answers need
no badge. A rejected concern displays `[concern not valid]`, unresolved input
displays `[needs input]`, and unmatched reported changes display
`[code changes unavailable]` without a diff action. Place the cursor on a claim
and press `D` to open its associated changes in a unified diff tab. Press `q`
to close the diff tab.

Changed claims must declare at least one change and are addressed only when a
reported change matches the actual diff. Answered and disagreed claims need no
code change. Needs-input and unmatched results remain unresolved. Every result
includes a non-empty summary with concrete reasoning. Addressed status
overrides stale presentation without changing the stored anchor freshness.

The default `review_runs.diff_viewer` value is `auto`. It prefers CodeDiff,
then Diffview, and otherwise uses doubt.nvim's built-in unified diff. Set it
to `codediff`, `diffview`, or `builtin` to select a viewer explicitly. A Lua
function may also be supplied as a custom adapter.

CodeDiff and Diffview receive temporary before/after data containing only the
claim's attributed textual hunks. Non-textual changes fall back to the
built-in viewer.

The manifest supplies semantic attribution; doubt.nvim calculates the actual
diff between the export baseline and the sealed agent-completion tree. Changes
not attributed to a claim are reported in the panel. Later worktree edits do
not alter claim diffs and appear as `[workspace edited after response]`. Review-run
diffs require Git, but normal exports continue to work without it.

Each export creates a `complete` helper. After all code changes, the agent
writes `results.pending.json` and runs that helper as its final step. The
helper requires one result per exported claim, captures and retains the exact
completion tree with a temporary Git index, then publishes `results.json`.
It does not modify the real index, branch, or commit history.

Results compose across exports by claim ID. Exporting newly added claims keeps
prior outcomes and diffs for claims omitted from the new run. Re-exporting the
same claim supersedes its older result, so it waits for the newer manifest.
